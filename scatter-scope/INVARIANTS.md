# SCOPE invariants

Hard rules the rest of the methodology must not contradict. When a procedure, brief, template, or tool here disagrees with an invariant, the invariant wins and the other is the bug to fix.

## I1. The oracle sees no code and no count

**Test:** read the brief an estimator received: does it contain a source line, a measured figure, a suspicion, or the name of a concept under study beyond the full module list? Any yes voids that estimate.

Why: the estimate's only value is that it is a prior. A hint turns it into agreement.

**Enforcement:** the brief template holds the permitted sections and nothing else; Pick records which brief each estimate came from.

## I2. A flag is a gap, never a count

**Test:** for every flagged concept, are the expected figure and the measured figure both on the pick table, with the gap between them? A concept flagged on a measured figure alone fails.

Why: a count has no meaning without what was expected of it; config is read everywhere and that is not a finding.

**Enforcement:** the pick table's columns; the methodology's Pick phase.

## I3. Explain verifies the instrument before reading for a cause

**Test:** does the revival report state what the B files are, whether the corpus held anything a reader would not meet, and whether the count holds, before any mechanism is named?

Why: a surprising count indicts the measurement first; a dictionary word in a vocabulary, or a session log folder in the corpus, produces a gap that no code change would close.

**Enforcement:** the revival message carries the instruction; a report that names a cause without the check is returned.

## I4. "By design" closes a flag

**Test:** can a revival end with no defect? If the report format or the owner's reading treats every flag as a fault to fix, the method has become a linter and fails.

Why: shared vocabularies read widely because that is their job. The method measures gaps; the owner decides which gaps are costs.

**Enforcement:** the Explain phase names the outcome; the pick table carries a disposition column with it as a value.

## I5. Methodology documents name no run's code

**Test:** grep this folder for the module names, type names, or feature names of any completed run; zero hits. The methodology speaks in kinds (module, concept, consumer, fact); a run speaks in instances.

Why: a run's noun surviving here rebinds the method to one codebase, and the next run inherits a frame it should not have.

**Enforcement:** the grep is run at authoring time against each finished run's vocabulary; this file is the tie-breaker when an example seems too useful to generalise. Abstract the example, keep its lesson.
