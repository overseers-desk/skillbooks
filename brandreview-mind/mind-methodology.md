# MIND — how the market holds one trading name, and whether a movement is the operator's own

**Phases:** Measure, Index, Name, Decide

## What MIND is

MIND answers four questions about one trading name, each run: whether the name is held better or worse than a year earlier, on instruments and in each market the operator targets; whether a movement in that standing is the operator's own or the market's; what the market's own words say about each movement found; and what the operator elects to change. The four questions map one to one onto the four phases, which is what the letters are for: Measure answers the first, Index the second, Name the third, Decide the fourth. Where a run cannot answer one of the four, it says so in that phase's own words and states what it would take, rather than answering an easier question in the same space.

A run is the same procedure each time. It executes a fixed set of detectors, the series in which a movement of the name shows, over matched windows a year apart, for the operator and for a panel of comparable businesses, and it writes the same tables with the same columns, so that the second run is comparable with the first and the tenth with the ninth. A change is a movement only where it is larger than the detector's own noise, and a movement is attributed before anything is said about it. A brand review that describes the name on one date can be written without any of this, and reads well, and cannot tell a change in the operator from a change in the market, nor a change from a wobble.

MIND is not a campaign, not a rebrand and not a content plan. It is a measurement discipline around one name, re-run on the cadence the operator sets, and its actions are the operator's decisions, read at the next run for whether they moved what they were meant to move.

## The unit of study

The unit is one trading name: the name the market uses to seek, rate and talk about the operator, whether or not the operator owns it as a mark. A sub-brand, a product name or a former name is a row inside the run, carried where the market still uses it, and is not a unit of its own until the market seeks it without the parent name attached.

The unit is not the website, the logo, the audience or a product. A website is one of the surfaces the name appears on. A product is what LAMP studies, and its standing in search is reported there. An audience is who holds the name, and a movement in one target market and not another is how a run sees an audience move, but the audience changes with the offer and the name outlasts both.

An operator trading under two names that the market treats as separate runs two units, each with its own panel and its own series. Two names the market treats as one are one unit, and the run says so and carries both spellings.

## The name terms

Every detector that reads search reads a set of name terms: the name, its spellings and misspellings, its abbreviations, and the name with the words the market attaches to it where those are how the name is typed. The set is fixed in the campaign's instrument list at the first run, one set for the operator and one per panel member, and every later run reads the same set. A term the market starts using is added with a dated seam, and the detector's series is read on both sides of it, since a detector re-pointed at different terms measures a different thing and its series breaks without saying so.

The set is built from the market side, from the rank database's report of queries containing the name and the console's report of queries on which the operator's pages appeared, and the run states how much of the name's impressions the set captured; a term outside the set carrying more of them than the cut-off the instrument list sets is added with a dated seam.

## The panel

The panel is the set of comparable businesses whose series a run reads the operator's against. It comes from the campaign's register of comparable businesses, which rates each candidate for closeness on stated criteria and groups the result into bands by closeness, and the run takes the closest band as its panel. The register is the campaign's artefact, revised as a dated file, and this methodology says only what a member needs to carry to be indexable: a name term set the shared detectors can read, the market it sells into, the reason it was admitted, and the window from which it counts.

A panel of one is not a panel; it is a second operator, and a movement it shares with the first is as likely two coincidences as one cause. The smallest useful panel is the band the register produces, and where the closest band holds fewer than three members the run takes the next band in as well and says so.

The market each member sells into is what lets Index tell the operator's market from the whole. Members sharing the operator's market move with that market's conditions; members outside it move only with conditions the whole market shares. A register that does not carry this attribute per member cannot support the second attribution, and Index then reports a movement as market-wide or own only.

A member entering or leaving the panel is a seam in the series, dated, and not a deletion. A member that closes, renames or merges stays in the register with its exit dated, so a prior run's panel figure can still be checked against the members that produced it.

## Windows, cadence and target markets

A run reads matched windows: the window the operator names and the same window a year earlier, this year against last, or the year to date against the same dates a year earlier. Two windows a year apart hold the same season, so a difference between them is not the season; a window read against any other is read against the season as much as against the market. Where the run's window differs from the prior run's, both are read: the matched window for the year-on-year figure, and the prior run's window for its open decisions.

The operator sets the cadence, and one bound on it is the instruments': a run comes at least once inside the shortest retention wall among the operator-only detectors, because a series that has fallen out of an instrument's retention cannot be read later by anyone. The first run reads the window a year earlier wherever an instrument's retention reaches it, and where it does not, reports the figure without a movement and states the date from which a movement will be readable.

The markets the operator targets are named in the campaign's instrument list, with the detector that can separate each: name search volume and console impressions by country, reviews by the reviewer's language, the public interest index by region. Measure reports each detector for the whole and for each target market it can separate, and Index reads the panel on the same markets. A target market no detector can separate is reported as such, and what Name says about it rests on the market's words rather than on a figure.

## The detectors

A detector is a series in which a movement of the name shows. Each is named here by the kind of instrument that supplies it; the campaign's instrument list names the instance, its floor, its retention wall and its query cap, and the run's headings call each detector by its name here. A run executes every detector the instrument list can supply and lists the rest as not run, whether because no instrument of that kind is held or because the operator has no such profile, account or listing, with what would supply each, so the operator can see what the run is blind to.

| Detector | What it detects | Instrument kind | Reach | Unit per window |
|---|---|---|---|---|
| Name search volume | The name is sought | rank database: keyword volume on the name terms, by country | panel and operator | queries per month, summed over the window |
| Name impressions and clicks | The name is sought, and the operator's page is the answer | search performance console: queries containing the name terms, by country and day | operator only | impressions, clicks, click-through, position |
| Share of search | The name is sought, relative to the panel | derived: the operator's name search volume over the panel's sum, per market | panel and operator | share |
| Public interest index | The name is sought relative to the panel, over a longer past than most instruments keep | public interest index over time: the name against the panel's names, by region | panel and operator | normalised index, read beside counts and never combined with them |
| Name modifiers | What the name is sought for | rank database and console: queries carrying a name term plus other words, ranked by volume or impressions | panel by the rank database, operator by both | each of the prior window's top modifiers' share of name queries, and the share held by modifiers outside that set |
| Review velocity and rating | The name is spoken of, and how warmly | review platforms: reviews posted in the window, by platform and reviewer language | panel and operator | new reviews, mean rating of new reviews, share at the lowest two ratings |
| Review themes | What is said about the name | review platforms: the share of new reviews carrying each theme of a fixed theme list, coded under it | panel and operator | share per theme |
| Public mentions | The name is spoken of beyond its own properties | rank database mention or backlink report, and public search on the quoted name terms, excluding the operator's own properties and the platforms already read | panel and operator, unevenly | mentioning pages or posts in the window |
| Social following and engagement | The name is seen and followed | social accounts: followers at window end, posts, engagements per post | panel and operator | followers, follower change, engagements per post |
| Business profile actions | The name is seen on its profile and acted on | the operator's business profile: views, and the actions the profile offers, calls, website clicks and the rest | operator only | views and actions |
| Direct and name-referred traffic | The name is sought and the operator's own property reached | the operator's analytics: sessions with no referrer and sessions from name queries | operator only | sessions, share of all sessions |
| Listing presence | The name is seen where its market looks | directories and intermediaries carrying the name: how many carry it, and the rating and completeness on each | panel and operator | listings, mean rating |

The three verbs in the second column, sought, spoken of and seen, are the three things a movement of a name can be, and every detector answers one of them. A run reports the detectors grouped by verb, so a movement in one verb and not the others is visible as such: a name more sought and not more spoken of has been advertised; a name more spoken of and not more sought has had an event.

The theme list under which reviews are coded is drawn at the first run from the themes the first window's reviews carry, and is the same list for the operator and every panel member. It is the campaign's artefact, dated, and a change to it is a seam. The coding is Sonnet-tier under the list, with the list frozen before the reviews of the new window are read.

Every detector has a floor, a retention wall and error windows of its own, and they are stated on the detector's row in the run. A rank database reports nothing, or a band, below a volume floor; a name under the floor is reported as under the floor, at most the floor's value, and never as zero, and it enters no mean, share or delta, with the count of what was struck stated beside the aggregate. A name under the floor on one run and above it on the next has crossed a floor, which is not a measured rise, and the row says so.

A change is a movement only where it is larger than the detector's own noise. The threshold is computed from the detector's own series before the new window is read: the spread of its year-on-year changes across the prior periods the instrument keeps, at the instrument's own reporting granularity. A change inside that spread is reported as within noise. A series too short for the computation reports its change and calls nothing a movement, and states the date from which it can. The threshold is computed the same way for each panel member's rows, each from its own series.

Where a run shares an instrument with a LAMP run of the same operator, it cites that run's measurement ground as LAMP's movement report defines it (`seo-lamp/lamp-methodology.md`): the retention wall, the error windows with their direction, the tag-break dates and the withheld-row fraction. It reads the known-instrument-defects section of the same document before drawing any window, rather than re-deriving either.

## Runs and the methodology

A run is one trading name read once, on one date, over the matched windows the operator names, in the campaign folder. It is a dated document that carries every figure it compares against, every open decision it reads, and every finding it makes, in the tables the artefacts section lists, so that a reader handed the run alone holds the series for what the run uses, and a reader handed two runs can lay their tables side by side.

A run reads the prior run before it measures anything. That is the first act of Measure and the reason the series exists. A run that measures first and reads later has redrawn a snapshot, whatever it says about trend.

Before a run is published, a fresh agent holding the run and its captures, and nothing else, reads it and writes its findings into the run. An agent told what the run concluded confirms it, so the reader is given neither the brief nor the reasoning. At this version the cold read is a paragraph and its checks are the invariants; it grows a class list, as a section of this document, when a defect has escaped a run, with the run that taught it named.

A run is committed before it is corrected, since correcting in place rests on the earlier text being recoverable. Captures a run makes, results pages, review exports and profile snapshots, go into the operator's capture series under that series' naming, committed, and not into the run's own folder.

## The phases

### Measure

1. Read the prior run. Write the carried-forward table: each detector's figure for the prior run's window and market, each open decision with the detector it named and its read date, and each finding by number and head. The first run of a name states that there is no prior run.
2. For each detector the instrument list supplies, pull the operator's series over the matched windows, for the whole and for each target market the detector separates, on the name term set. File the capture.
3. Compute each detector's threshold from its own prior periods, before reading the change.
4. Write the detector table: one row per detector, market and window, carrying the figure a year earlier, the figure now, the change, the threshold, the floor and retention note, and a verdict from the fixed set: moved up, moved down, within noise, under floor, not readable with the seam or date that blocks it, not run with the instrument kind that would supply it.
5. Read each open decision by the detector it named and enter its state on its row of the carried-forward table: moved as expected, moved otherwise, not yet readable with its read date, unreadable where it named no detector or a seam blocks the window.

Measure reports and does not attribute. A movement it finds is a movement in the operator's series and nothing more until Index has read the panel.

### Index

1. For each detector that sees the panel, pull each member's series on its own name term set, over the same windows and markets, and compute each member's threshold from its own series.
2. Write the panel table: one row per member, detector, market and window, with the detector table's columns and verdict set.
3. Attribute each of the operator's movements. More than half the members that could be read moved the same way past their own thresholds: market-wide. Only the members sharing the operator's market moved: the operator's market. No member moved: the operator's own. The panel splits, or the floor hides it: unattributed, with the observation that would settle it and who can make it. A detector that sees the operator only has no panel column, and its movement is reported under an unindexed heading, which is all Name may then say about it.
4. Write the standing table: the operator's rank and share among the panel on each detector that sees both, per market and window, so that better or worse is stated against the panel as well as against the year before.

### Name

1. For each movement attributed to the operator or left unattributed, gather what the market's own words say about it, from the run's own detectors: the modifier mix, the review themes, the public mentions, and the operator's published claims over the window.
2. Write the findings table: one numbered finding per such movement, and one per detector the operator asked about that did not move, each carrying the detectors it rests on, the attribution, the market's words, and one of five fixed heads under which the prior run's findings lie beside it: positioning, competitors, audiences, presence, reputation. A finding drawn from the model's own account of the market, with nothing in the run behind it, is marked as opinion.
3. Mark each finding moved, unmoved or new against the prior run's findings under the same head.

Name ends the run. It chooses nothing. What to do about a finding is decided at Decide, and a run that ends by recommending has taken that phase from the operator.

### Decide

Decide is the operator's phase. The operator reads the findings and elects what to change, and AI clerks the decision table: one row per decision, carrying the finding number it answers, the detector and market that would show it worked, the direction and size expected, and the date it can first be read. A decision made between runs, on a finding of the last run, is a dated decision document in the campaign folder, in the same shape.

The next run's Measure reads each open decision by the detector it named, and a decision that cannot be read is a finding of that run's Measure, not a footnote.

## Seams and floors

A seam is a dated event after which a series cannot be averaged with its own past: a name change, a change to the name term set or the theme list, a platform migration, a review import, an account merge, a change in what an instrument counts, a panel member entering or leaving. A run lists its seams with dates and charts them as lines. No mean, share or before-and-after figure straddles one; the figure is split at the seam or not given.

A floor crossing is a seam of the instrument's making. A name that was under a rank database's floor and is now above it has a first measured figure, not a rise, and the row says which.

## Model allocation

| Phase | Tier | Rationale |
|---|---|---|
| Measure | Sonnet-tier, under the instrument list | Pulls, thresholds and the detector table under stated rules, with the seams and floors already named |
| Index | Sonnet-tier, under the register | The same pulls per member, and an attribution that follows from the tables; a split panel is reported, not resolved |
| Review coding | Sonnet-tier, under the frozen theme list | Coding under a list is rubric work; drawing the list at the first run is Opus-tier |
| Name | Opus-tier | Reading the market's words against a measured movement, and holding a finding at opinion where the run has nothing behind it, is where the run's value is made or lost |
| Decide | Human, with AI clerking | The operator elects; the clerk keeps each row readable at the next run |
| Cold read | Fresh context, tier set by what the run will be used to decide | The invariant checks are mechanical; the defect outside them is not |

## Versioning

A run states its date, and the date fixes which reading of this document governed it.

A run is a dated document beside the earlier runs, and the series is the set of them. There is no standing series file appended each cycle, because such a file is cited by figure and rewritten every run, which strands each citation. Instead each run restates, in its carried-forward table, every prior figure and every open decision it compares against, so a reader handed one run holds the series for what that run uses. That restatement is a merge requirement: a run reads the prior run in full before writing, and carries forward what its new work does not supersede.

The register and the instrument list are cited by figure and are versioned, a new dated file beside the old. A run is corrected in place: the same file, the same name, and nothing in it pointing at what it said before, committed before it is corrected so the earlier text is recoverable.

No document assumes an order of reading. A reader opens whichever one was handed over, and no run rests on another having been read first, the prior run included.

## Relationship to the other methodologies

LAMP (`seo-lamp/lamp-methodology.md`) and MIND divide the series between them. LAMP measures whether the market can find one product and what finding it is worth, and reports a page's brand share beside the product's standing without folding it in. MIND measures how the trading name above the products is sought, spoken of and seen, and reads it against a panel. Where the two share an instrument for one operator, LAMP's movement report holds the measurement ground and MIND cites it.

The claims Name tests the market's words against are the ones SAGE (`pmf-sage/sage-methodology.md`) ruled when it established the offer and PLACE (`market-place/place-methodology.md`) recorded when it positioned what was built; where a claim has a home there, Name cites it rather than restating it. A finding of Name about which target market moved is what a SPAR campaign's segments are drawn from when the operator goes to market.
