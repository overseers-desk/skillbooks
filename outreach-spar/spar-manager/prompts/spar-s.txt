## Your deliverable

Write one file, __OUTFILE__: YAML front matter between `---` fences, then the body.

The front matter carries what the harness applies:

        sweep_iteration: __ROUND__
        discovered_via: __SOURCE_NAME__ (entry 412)
        s_note: listed as the responsible person on the register entry
        star_rating: 3
    source_status: partial — 120 of 400 entries read, A–F
    reconciliation: |
      400 entries in the source; 120 read this round; 96 in scope after the
      criteria; 12 already on the roster; 84 rows returned.
    sweep_feedback:      # optional; omit when the source taught nothing
      - kind: new-source
        note: the register links a state association directory at <url>
    escapes:             # optional; a member an earlier round should have caught
      - member: Vale Holdings
        verdict: missing-keyword
        note: trades as "co-op", which round 1's queries did not cover

Row conventions:

- `stem` is the row's identity and its filename: lowercase slug, hyphens only, `firstname-lastname-organisation`, unique within the segment. Where no individual is named, an organisation-slug stem with a blank `contact_name` is a legitimate row — the profile phase resolves the person (SPAR-P §4.1).
- `organisation` carries the organisation the contact belongs to. A row with neither an organisation nor a contact name is a fragment, not a find.
- `discovered_via` names this source and, where the source has entry numbers or URLs, the specific entry, so a later round can re-find the row's origin.
- `s_note` is why this row is in the roster: the signal in the source that justified it. One line.
- `star_rating` is 0–5 against the segment's `rating_rubric`. A 0 goes with a `date_excluded` date and an `s_note` saying what made the row stale (SPAR-S §8a).
- Values are single-line: no tabs, no newlines inside a value. The roster is a TSV with no quoting, so a tab in a value would split the row.
- Use only the column names listed above. A fact that has no column belongs in `s_note` or in the body.

`source_status` is the status line the sweep file will carry after your work, and it leads with one base token — `unharvested`, `partial`, `exhausted`, `unreachable` or `stale` — with your reason after it. `exhausted` is a claim about the whole source and needs the evidence in your body to back it: what you read, and how you know nothing is left. `partial` with a precise reason is worth more than an `exhausted` you cannot defend.

`escapes` is for a member you met that an earlier round should already have caught: the row goes in `rows_new` like any other, and the miss goes here with a `verdict` naming its cause (`missing-keyword`, `missing-source`, `source-not-exhausted`, `filter-too-tight`, `process-defect`). The harness appends it to the sweep file's standing escapes list, where it stays as a test case the next round has to catch, so an entry with no verdict is dropped rather than recorded: the verdict is what decides which part of the sweep head gets fixed.

`reconciliation` reconciles your count against the source: how many entries the source holds, how many you got through, how many survived the criteria, how many were already on the roster, how many rows you returned. This is the number that turns into the round's coverage.

The body is the source-work narrative: how you enumerated it, the queries or paths that worked, what the source's shape taught you about this market, the judgement calls on borderline members, and — where the status is `exhausted` — the evidence for that claim. A later round starts from this file, so write it for the reader who has the sweep record and none of your session.

## Working notes

__COST_LINE__ Rate-limited sources are worth waiting on, one page at a time, rather than parallelising into a block.

Web search is the secondary instrument here, for resolving the named individual behind an entry the source lists only as an organisation. For a page a plain fetch cannot read, the dispatcher resolved a browser command for this host: run `out=$(mktemp); __BROWSER_CMD__ "URL" > "$out" 2>/dev/null` and read `$out` — redirect to a file rather than pulling a rendered DOM into context. For a LinkedIn or Facebook page, prefer the matching site skill: it paces through the same arbiter, so it does not collide with the other workers on this round.

This session is one-shot: when your turn ends, the process exits. A command moved to the background promises a notification that will never arrive here, so run long commands in the foreground with a generous explicit timeout (`timeout: 600000` on the Bash tool, or `timeout 540 <command>`) and wait for the result. A queue wait of several minutes behind other browser work is normal.

When __OUTFILE__ holds the front matter and the body, you are done — stop there. The harness applies your rows to the roster, updates the source's status, and records the round; anything it rejects comes back to you as a fix instruction with the row named.
