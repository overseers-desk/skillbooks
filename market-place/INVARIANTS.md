# PLACE invariants

Hard rules the rest of the methodology must not contradict. When a procedure, template, or example here disagrees with an invariant, the invariant wins and the other is the bug to fix.

## I1. Pain numbers have one authoring home

**Test:** for any pain number cited in a run, grep the run for its defining sentence (the bold name and the sentence after it): one file holds it. Every other file carries the number, or the number with a short label, and no second definition. A second file that defines a pain, or a number that means different things in two files, fails.

Why: the numbers are the spine; a second home lets the corpus, the field, and the code drift apart while still appearing to agree.

**Enforcement:** the taxonomy file says it is the authoring home at its head; the run README names it; renumbering is one change across every citing file.

## I2. The market files and the product file do not mix sources

**Test:** read any file in the run: is it written from the field (quotes, rivals, discussion) or from the code (coverage, paths, ceilings)? A file that does both fails, and so does a field file that carries the operator's product as a row.

Why: the product read through its own field review is the failure the method exists to prevent; the owner needs to know which sentences the code backs and which the corpus backs.

**Enforcement:** the product file says at its head that it is the one written from the code; the field matrix excludes the product; the run README states which files are which.

## I3. Every corpus entry carries a link and a date, and precision is never invented

**Test:** for each entry in the quote corpus, is there a working link and a date (exact, or marked approximate)? A quote without a link, or a date sharpened beyond what the source gives, fails; a paraphrase not marked as one fails.

Why: the corpus is evidence, and its entries are quoted downstream as user language; an unlinked quote cannot be checked and an invented date cannot be trusted.

**Enforcement:** the entry form in the Poll procedure; the run README's conventions; the paraphrase marker is a standing debt.

## I4. Rarity is rated against the recorded field, not against the world; position is argued against the marked competitors, not against the field

**Test:** for each capability rated rare or unique, does the clause say which surveyed products come closest, and is "unique" phrased as documented in none of the surveyed products? A claim that nobody anywhere does this fails. For the positioning, does the matrix carry a competitor mark with its rule stated, and do the positioning sentences name rivals from the marked set? A file that calls every surveyed row a rival, or a positioning sentence whose rival is an unmarked row, fails.

Why: the field matrix records self-descriptions of a surveyed set; it cannot prove a negative about the world, only about itself. And the survey answers a supply question, so it is wide; the buyer weighs a few products at one moment, so the competition is narrow; the two are not the same set, and position argued against the wide one is argued against nobody.

**Enforcement:** the Contrast procedure's wording; the matrix head states that cells are self-described and unconfirmed where not confirmed, and states the competitor rule; Establish names the competitor set before it names a move.

## I5. The name and the outward claims stay inside the Audit

**Test:** for the product's name and for any positioning sentence, can you point to the coverage row that backs it? A name promising a function class the Audit records as None, or a claim the Audit records as Partial stated as whole, fails.

Why: an overclaiming name is read as positioning intent and then built towards; the Audit is the only file that knows what was built.

**Enforcement:** Establish reads the Audit before it reads anything else; the naming note, where written, cites coverage rows.

## I6. Methodology documents name no run's product

**Test:** grep this folder for the product nouns, field nouns, and source names of any completed run; zero hits. The methodology speaks in kinds (product, operator, rival, venue, pain); a run speaks in instances.

Why: a noun surviving here rebinds the method to one market, and the next run inherits a frame it should not have.

**Enforcement:** the grep is run at authoring time against each finished run's vocabulary; this file is the tie-breaker when an example seems too useful to generalise.
