## The situation it describes

Each apostrophe terminates the single-quoted string, so the command handed to `/bin/sh` is malformed, and the shell fails with "Syntax error: Unterminated quoted string" before any tool command runs. Because the hook fires on every Bash invocation, every Bash call in the session is rejected, including the trivial command `true`. The reporter verified this rather than assuming it: it tested `true`, and it tested inside a fresh subagent, establishing that subagents inherit the same broken configuration and that no execution path in the session can reach a shell.

The semantic-compressor skill depends on a bundled control script, run via Bash, which performs workspace, inventory, validate, and apply operations and provides a deterministic gate. The skill's contract forbids recreating those operations with ad hoc shell or file tools. With Bash dead and reimplementation forbidden, no valid candidate output can exist. ## Why it exists

Three reasons are visible in the text. First, contract integrity: the skill's value is that anything between RESULT tags passed a deterministic gate, and an honest empty ERROR preserves that guarantee where a plausible fabrication would destroy it. Second, diagnosis over symptom: the report converts "compression didn't happen" into a verified root cause, a recurrence statement, and a concrete fix, which are precisely the three hidden questions the HITS discipline says a problem-solving report owes its reader. Third, it distinguishes environmental failure from content failure through the state taxonomy, so the receiver spends effort on the hooks configuration and none on the file.

It also carries an incidental design lesson: user-facing prose embedded inside a machine-quoted command string is fragile, and a guard whose deny message can break the guard is better served by keeping the prose in a script file or a quoted argument mechanism.
