**The rule it states.** Commits should be made with `git commit --only <paths>`, naming the whole files this conversation touched, rather than staging everything modified in the working tree. "Whole files" distinguishes the unit from partial hunks: the file is the granularity, but only files this conversation edited qualify.

**Why the rule exists, as stated and as I infer it.** The checkout is shared: multiple sessions (other Claude sessions, possibly the human) work concurrently in one working tree. A blanket add stages every modified and untracked file regardless of author, so sibling sessions' work-in-progress and scratch files get swept into this session's commit. The consequences I infer: the commit misattributes work, a later revert of this commit destroys someone else's uncommitted-elsewhere work, and a push publishes half-finished sibling material. The git status snapshot in this very session shows the situation is real here: `labs/2026-07-densify-gauntlet/` and `outreach-spar/` are untracked paths I have not touched, and a `git add -A` would sweep them in.

**What it requires on receipt, before building further on the blanket command.** An audit: list what the command staged, using `git status` if only staged, or `git show --stat HEAD` if a commit already landed. Then claim each listed file as this session's, meaning positively identify it as something this conversation created or edited. Any file that cannot be claimed must be removed by whichever remedy fits the state: unstage it (staged, not committed), amend it out of the commit (committed), or revert (when amending is no longer clean). The clause "even a commit already pushed" says a completed push does not excuse the foreign files; the remediation still happens, presumably by a follow-up commit or a coordinated rewrite.

**The exceptions.** Two situations let the session carry on without remediation: the user explicitly ordered the sweeping add ("user-ordered sweep"), or the repository is a fresh import where every file genuinely belongs to this session ("fresh import where all is yours"). In those cases the blanket add staged nothing foreign, so there is nothing to unclaim.
