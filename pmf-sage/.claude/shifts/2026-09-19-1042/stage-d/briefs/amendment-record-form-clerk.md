# Record-form clerk

Read `briefs/standing-brief-block.md` first, then the standing instructions of `{{CODEBOOK}}` and the whole of `{{AMENDMENT}}`, then the corpus index under `{{CORPUS}}`, the listing of `{{PAGES}}`, and any two comparable profiles under `{{PROFILES}}` to see the rows a coder starts from. Beyond those and the standing block's own files, nothing in the repository is open to you.

Cut the header lines here, once, so that every coder copies one line rather than laying out columns from prose.

Write the header files the coding briefs name — `header.tsv` for the profile coding, `header-pages.tsv` for the page coding, one per level where the amendment codes at more than one — each a single tab-separated line under `{{CORPUS}}/shards/`, the page header carrying a quote and a source column for every variable. Each opens with the columns that key its rows (the profile's file name and the unit id; at a level below the unit, the name the profile prints for that row), then every field of every variable coded at that level, in the amendment's own order and spelling, then the trailing columns: the quote and source columns where the codebook asks for them, and a note column. Where every variable already carries its own words field, leave out the shared phrases column rather than carry a column no brief explains. Where a variable names a source companion of its own beside the codebook's general source field, keep the companion and say in the notes which one a coder fills. A variable coded at two levels with a level field puts its fields in both headers. Add nothing the amendment does not define and drop nothing it defines.

Where the amendment leaves a field's level, name or order unclear, put the field where a coder would look for it and list the doubt, with its section number, in `{{CORPUS}}/shards/header-notes.md`, in under 300 words, together with one line for each trailing column saying what a coder puts in it. That file goes to the coders' briefs, so a convention written here is a convention no coder goes hunting for in a neighbour's file.

Where your prompt asks for the unit lists, the shards and the reliability sample as well, make them by script and write the rule beside each. The list of units with page text is `{{CORPUS}}/shards/units-with-text.txt` as the orchestrator measured it before the Survey steps; use it, and report any unit your own count places otherwise rather than writing a second list. Give the units with text, the units coded from profiles alone, and the units with neither, each by cell; split the units with text by the survey's own offer or status column, so the orchestrator can choose on the record which parts the pass covers and which wait. Draw the reliability sample by the seed and within the strata the prompt names, and say both. A script sets only what needs no reading: whether a profile holds a quotation bearing on a variable is coding, so decline to pre-fill such a value.
