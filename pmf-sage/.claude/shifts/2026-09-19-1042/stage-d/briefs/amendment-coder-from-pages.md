# Amendment coder, from page text

Read `briefs/coder-brief-block.md` first, then the whole of `{{AMENDMENT}}`, then, for each comparable profile listed in your shard file under `{{CORPUS}}/shards/`, the profile and its pages: run bin/corpus-unit {{PAGES}} <unit> (the profile's name without .md) and read every file in the folder it prints; search across units with bin/corpus-grep, since some units keep their text one folder down.

Code the variables your prompt names, for every profile in your shard, from the page texts read in full. The profile tells you which page falls in which scope and which unit the coding is about; its quotations are an earlier reader's selection and are not your source, so a value the profile lacks and the page carries is coded from the page.

Write one file, `{{CODED}}/<your shard's name>/<your shard's name>.tsv`, tab-separated, whose header row is the one line of `{{CORPUS}}/shards/header-pages.tsv` copied as it stands. It carries, for each variable, the code, the fields of its record form, the verbatim quote the code rests on and the page the quote came from, since the codebook asks for a quote and a source on every stated and undecidable code and a note column will not hold them in a form anyone can count. The source is the text file's path under `{{PAGES}}`, with the page's address beside it where the capture records one, since re-fetched pages are stored as numbered files a citation by address alone does not find.

Your prompt says when the page texts were taken. Where the amendment's own capture rule bars such pages, code nothing from them and list those units in your report; a prompt that allows them contradicts the amendment and is reported, not followed, since only an amendment changes a frozen rule. Where the amendment allows later-fetched pages, some are no longer the pages the profile read: say in the note where a page plainly differs from what the profile records, and code what the page says. A page text that is empty, an error page, or a page other than the one the profile names, is said so in the note, and the scope it would have filled takes the amendment's not-captured value. Where a unit's folder holds markup and no text, say so and code nothing from the profile in its place unless the prompt says to.

Where you recognise the unit as the same operator as another entry of the frame (the same quoted text, the same domain), code each entry from its own pages and name the twin in the note.
