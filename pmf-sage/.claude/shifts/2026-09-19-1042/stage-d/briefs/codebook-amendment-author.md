# Codebook amendment author

Read `briefs/standing-brief-block.md` first, and the three files it sends every clerk to, `/usr/local/src/aesop/pmf-sage/sage-methodology.md`, the phase document `/usr/local/src/aesop/pmf-sage/sage-S-survey.md` and `briefs/venue-situation.md`, then `{{CODEBOOK}}` with every amendment already in it, and `3-decisions/questions-numbered.md`, which holds the parameters a buyer meets as numbered questions and nothing of what this venue does, each question marked with whether it came from the method's named cards or from a parameter of this run's earlier decisions, the second being a question a draft raised and not one the market did. Beyond those files nothing in the repository is open to you: no frame, no comparable profile, no finding, and nothing else about this venue.

The cards will ask the corpus questions it has not been coded for, and a card whose question no variable answers ends up withheld for want of a count. Write one amendment, `{{AMENDMENT}}`, in the codebook's own form (definition, values, decision rules, the verbatim phrase a coder captures, the missing-value codes), holding: the variable step 4 of the Survey procedure asks for, whom each operator sells to, coded from what the operator publishes, with "not stated" as a value, a second field for the kind of buyer an operator names within each class it addresses, and, where the one who pays is not the one who takes part (a funding scheme, an employer, a relative), which of the two the variable codes, and how a coder treats an operator that addresses several buyers; one variable for each of the four shape dimensions of step 1 of the procedure; and one variable for each question of the numbered list that no existing variable can answer, saying beside each question, by its number in `questions-numbered.md`, which variable, old or new, answers it. Mark in the amendment each variable that answers only a question raised by an earlier decision, so a card resting on it says so. Silence is a value of its own on every variable, never folded into a practice. The amendment's examples name no venue. Draft it blind, as the codebook was drafted: from what operators of this kind could publish, and from nothing this venue sells or wants. The venue-situation note is open to you for the offering's shape and the buyers still standing, so the variables cover the dimensions a card will rule; nothing in it is a value to code toward. Where a term can attach to several things an operator sells, code the offering's terms apart from the others': one payment variable gathered camp, party and event deposits with lesson terms, so seven of ten priced units counted were not lessons and a card flipped on the reading. Code camp, party and event payment terms apart from lesson or session terms, and rule on a fee paid at the start of a period of sessions. Give it a version and a date; it is frozen when you return it.

Where operators address several buyers, say how a class figure is reported. Both runs of the third batch barred a coder from ranking a main class and reported a presence rate for each class beside the distribution over units addressing one class alone; that form is available to you, and a card that needs one class an operator would then need a synthesis rule, which you may write or leave to a later amendment and say which.

Six things decide whether a coder can run it.

A closed list is the test. Where a rule gives a list of values and also describes inclusion in words of its own, two careful coders apply different rules and part: state the list, and let the test be membership of it. Where membership alone would count a word's presence rather than what the variable means (a buyer word in a sentence about parking), say what else the sentence must do, in questions a reader can answer, and expect the variable to be coded in two steps, a script for the vocabulary and two readers for the judgement.

How a listed phrase matches is part of the list: inflection and plural, a possessive, an inserted word, spelling variants and compounds ("car park" and "carpark"), an ampersand for "and". Strict matching declines plain statements that differ by one word.

Each closed value is written once, in one value table the variable's section, any summary and any appendix point to.

The amendment says what keys a row at each level it codes at, in the columns the coded tables already join on, which the orchestrator names in your prompt; prefer such a column to a ladder of your own. Try the key on a profile that leaves its unit unnamed and on one that holds several listings under one file.

The amendment says what a page not in the codebook's language takes, and what a unit with no stored pages takes where it is coded from its profile, with the denominator each rate then uses; coders and the strike list otherwise each settle both. Read the earlier amendments' scope rulings for what they bar your variables from reading, and state each such coverage limit beside the variable it binds.

The amendment's size is a coder's working day. Say which variables a card is most likely to cite, so the first pass can code those and the rest can wait until a card asks for them; say which variables you would code over the whole corpus and which on a seeded draw, and of what size.

Each decision rule is tried before it is frozen, and the trial is run on passages you did not choose: a borderline an author invents is one the author has already settled. A worked case is a sentence from the corpus, and the corpus is closed to you, so write no worked case of your own: an invented case gets cited by coders as licence, as one reviewer's was on three units. State each rule's wording, check any format example against the format it illustrates, and name the rules whose trial you could not run, so the orchestrator can put them to a second clerk on passages drawn by seed from the stored pages, whose sentences then stand as the worked cases.

The file is written to the repository's markdown rules, dollar signs escaped, and its front matter names the codebook version it amends.
