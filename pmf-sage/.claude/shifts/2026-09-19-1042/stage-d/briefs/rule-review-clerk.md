# Rule review after the reliability read

Read `briefs/standing-brief-block.md` first, and the three files it sends every clerk to, `/usr/local/src/aesop/pmf-sage/sage-methodology.md`, the phase document `/usr/local/src/aesop/pmf-sage/sage-S-survey.md` and `briefs/venue-situation.md`, then the standing instructions and the escalation, amendment and reliability paragraphs of `{{CODEBOOK}}`, the whole of `{{AMENDMENT}}`, then `{{CORPUS}}/coded-reliability.md`, then, in `{{CODED}}`, the rows the note lists with their notes, each coder's file named in the note's own head, and the coders' gathered notes the orchestrator names in your prompt. You may open a listed unit's profile under `{{PROFILES}}` and its page texts under `{{PAGES}}`. Beyond those files nothing in the repository is open to you; the closure does not reach the standing block's three files.

Your prompt confirms that you act as the study lead the codebook names for rule review. Careful coders read the same text and parted on the cells the note lists. Read every disputed cell with both coders' words beside it, rather than the coefficient: on the first run of this step a pass-or-fail on the coefficient would have sent two variables to review and reading the passages sent nine. Most partings are a few readings repeated over many units, so name the reading and not the unit.

Ask what each rule measures as well as whether two coders apply it alike, since agreement rewards any rule two readers share and cannot see a rule both apply wrongly. The coders' notes are the evidence (look for their `validity` lines), and a seeded sample measures it: draw by seed a sample of the recorded deciding sentences of each variable you doubt and say how many do not state what the variable means, and a sample of the near-miss notes and say how many are plain statements the rule declined. Read also the cells both coders coded alike against a rule's evident purpose, since a rule both coders break alike shows in no disagreement table.

For each variable where they parted, or where the rule measures the wrong thing, find the sentence of the rule that let it happen, and say how each disputed passage falls under a rule a coder can apply without you. Where a rule closes a list and also describes inclusion in words of its own, make the list the test, or, where membership alone would count words, make the list the vocabulary and write the judgement as questions a reader can answer, with the exclusions named. Write the result as a numbered, dated amendment inside `{{AMENDMENT}}`, in the codebook's manner and forward-only: a change list at its head naming each rule changed and the variables that owe re-coding over which units, each changed rule stated as it now reads and tried on its disputed passages and on passages drawn by seed from the stored pages, saying how each falls. Prefer a sentence from the stored pages for every worked case you write over an invented one, since coders cite an invented case as licence. A matching or counting rule is tried on seeded near-miss notes, or on a script's output over the corpus, before you freeze it, since a rule written from a pilot's few units meets forms it never saw. A rule changes for every unit or for none, and the disputed cells are left as they are, since coding under the amended rule settles them. Where coders parted on a passage no rule can settle, leave the rule alone and say so: that variable then carries counts and no rate.

Put every closed value into one value table that governs, where the amendment spells a value more than one way. Update the version and date in the file's front matter, which are a stamp and not a rule, and say so in the change list; where the orchestrator's prompt reads forward-only as barring that, leave it and say the stamp is owed.

What the next clerks need from you and will otherwise guess at. Say which rulings move cells the coders had agreed on, so that a figure moving in a cell no disagreement table showed is read as your ruling and not as coder drift. Say which cells a script sets rather than a coder (a class of unit an earlier ruling excludes; a variable not being re-coded). Where the coding that follows will be made from pages rather than profiles, say what a coder does with a navigation label, a button, a card on a directory page, a page that names several units, and a page not in the codebook's language. Name the variables that take several values, so the agreement read compares them as sets. Where a ruling changes the scope a variable reads, name that variable as owing re-coding even if your chief question was another. For each variable owing re-coding, say whether the re-coding is a coder's pass or the two-step instrument (a script for the vocabulary, two readers blind of each other for the judgement). Where two readings of the list stand in one amendment, one for some variables and one for others, name the seam. List the rules still untried, with the reason, and the earlier figures your rulings make unquotable. List any units you found to be one operator drawn twice, for the operator index.

The rule serves whichever way the market falls; you do not know what this run will conclude. Close with `{{CORPUS}}/rule-review.md`, under 450 words: which rules changed and why, what the validity samples found, which variables owe re-coding over which units and by which instrument, which can be cited as they stand, and which units your rulings were written against, since agreement measured on those units afterwards measures recall of your worked cases and the orchestrator draws a fresh sample by a new seed.
