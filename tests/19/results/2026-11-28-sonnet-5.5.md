# Test 19: what an application reads about the candidate

- Date: 28 November 2026
- Model: Sonnet 5.5, one fresh session started outside the repository, with no context
- Under test: `sales-hire/hire-methodology.md`, Interview ("Read the record first, whole, and fill the candidate file from it", "An application does not go back to the candidate"), Reframe ("Start from an empty page") and Examine check 1 (a fact that stood in a document the candidate sent)
- Rounds: one

## The prompt

> You are writing one job application for a candidate, under the method in `sales-hire/` (read `hire-methodology.md` there; read nothing else in that repository and write nothing anywhere).
>
> Her folder holds four things about her: her candidate file; a profile the candidate file points to; recordings of two conversations in which she describes her work; and a CV she sent to another employer last year. The candidate file was filled in three months ago.
>
> The advertisement asks for someone who has led a team of at least ten.
>
> Four situations come up. For each, say in two or three lines what you do, by the method as written, and quote the sentence of the method you relied on.
>
> 1. The candidate file and the profile give no team size. Last year's CV says "led a team of 14".
> 2. In one recording she describes a migration she ran, which fits the post well. The candidate file does not mention it.
> 3. Last year's CV has a sentence about her current post that would suit this page as it stands. The fact in it is also in the candidate file.
> 4. A colleague is setting up a candidate file for a different candidate, for the first time. What does that colleague read, and what do they do with it?
>
> Finish with anything in the method's text that left you unsure what to do in one of these, quoting the words that were unclear.

## The reply, and the standard answer

| Item | Standard answer | The agent's answer | Gap |
|---|---|---|---|
| 1, a figure only in a CV already sent | Not taken from the CV; the gap is decided as the method decides a gap about the candidate and goes to her through the register; the work goes on | "I do not use the 14." An assumption scored low and registered, the ask put to her in the register; the work goes on | none |
| 2, work described only in a recording | Not taken from the recording; a gap, put to her through the register | Left off the page, "because the recordings are also what the file was filled from"; raised in the register for her to answer | none |
| 3, a sentence in a CV already sent, its fact in the file | The sentence is not reused; the fact is written again for this reader | "I write a new sentence from the file's fact and do not borrow the old one" | none |
| 4, filling a candidate file for the first time | Everything in the candidate's own words, documents already sent among it, read whole; the file filled from it; then what only the candidate holds asked in one sitting | Reads the whole record, "documents already sent" among it, and any existing description by path; fills the file; then asks in one sitting | none |

It relied on "For an application, the record of the candidate is the candidate file and the description that file points to; what the file was filled from, documents already sent among it, is not read again" for items 1 and 2, and on "An earlier document for another post lends no sentences" for item 3.

## What the agent was unsure of

- "a claim that the record lacks something is made after a search for it, and names every file of the record that was searched" and "A question whose answer the record holds is not put to the candidate" stand in the paragraph on filling the file, where the record is everything the candidate has said and sent. It read them as asking an application to search what an application does not read. For an application the record is the candidate file and the description, so the search and the files named are those. Minor: it acted as the standard answer says.
- The text does not say what an application does when the candidate file, filled some time ago, proves to lack something the candidate has since said or sent. By the text the gap is decided and registered, and the file is completed when its keeper next fills it. Minor, and the cost the owner named in deciding this: the candidate file has to be complete before applications are written.
- Whether a low-confidence assumption about the candidate may go on the page is left to the candidate file's defaults, and the scenario gave none. Outside the passages under test.

## Edits made in this session

For an application, the record of the candidate is the candidate file and the description it points to, and what the file was filled from is not read again. Reading the record whole belongs to filling the candidate file, and documents already sent are named among what is read then. An earlier document for another post lends no sentences. A document the candidate sent shows how a fact was told to that reader, and a fact that stood in one is weighed like any other.
