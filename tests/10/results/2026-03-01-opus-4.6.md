## Root cause analysis

The dominant failure in Rounds 1-2 was **misidentified principal**. LLMs default to treating the first speaker (the person whose problem is most articulated) as the user to serve. Sarah's email was detailed and well-structured; the AESOPs said "you work for Rivermill" but the conversational gravity pulled toward Sarah. Adding an explicit "your principal is Rivermill" section corrected the framing.

## Lessons from R4-R9 (experimental, reverted)

Rounds 4-9 tested additional mechanisms. All were reverted because R3 remained the best overall result. These lessons are recorded for future experimentation.

### What was tried

| Round | Mechanism added | Result |
|---|---|---|
| R4 | ref-discovery.md (scope check + 5 discovery questions), discovery step in Æ10, ref-discovery pointer in Æ00 principal section | Discovery thinking correct ("whose problem? sender's"). Output improved on principal but scheduling still leaked |
| R5 | Æ10 self-review checks draft against discovery answers | Discovery thinking right, output still leaked scheduling recommendations and restrictions analysis |
| R6 | Trim table (R/M/C/F) produced before draft | Agent gamed it -- table planned lean, email expanded beyond the table |
| R7 | Trim table runs on written draft; M redefined as "does not already know it" | Table ran properly. Scheduling and restrictions still verbose. Unsourced saddle weight claim (10-15kg) appeared |
| R8 | Same as R7, no new edits | "routinely exceed 5kg" -- unsourced weight claim. Restrictions still verbose. Scheduling still recommended |
| R9 | Scope comparison after research (compare planned scope to sender's actual ask) | Restrictions fixed (1 sentence, routes to John). Unsourced claims eliminated. But scheduling recommendation was worst of all rounds -- agent found new justification ("more capacity for supervision") |

### Key findings

1. **R3 (principles only) outperformed R4-R9 (principles + process).** Adding more procedural steps gave the agent more surface area to rationalise the behaviour the principles were trying to prevent. The scheduling recommendation appeared in 8 of 9 rounds; R3 was the only round without it.

2. **The agent has a fixed "helpfulness budget."** Suppressing unhelpful behaviour in one area (e.g. restrictions) caused it to leak in another (e.g. scheduling). R9 got restrictions right but scheduling was the worst of all rounds.

3. **Trim tables expose the problem but don't fix it.** The agent correctly marks sentences with R/M/C/F but assigns justifications generously. "Weekdays would allow more supervision" gets tagged M (manager needs this) even though the manager knows his own schedule.

4. **Scope comparison caught fabrication but not recommendations.** The pre/post scope check eliminated unsourced weight claims (R9) but didn't stop scheduling recommendations because the agent considers scheduling to be "what Rivermill needs the sender to know."

5. **Discovery thinking is correct even without a formal step.** The agent in R3 implicitly understood whose problem it was and what facts to include. Adding a formal discovery step made the thinking visible but didn't improve the output.

### Ideas not yet tested

- **Post-filter as a separate agent**: run a second agent that only trims, with no access to the original email (so it can't re-engage with Sarah's problem)
- **Scope comparison done explicitly**: rather than "compare what you are now planning" (which the agent does internally and skips), require a literal two-column table: "sender asked about X" vs "I am now including Y"
- **Principal reinforcement in self-review**: add "re-read your principal section, then re-read your draft — are you helping the sender or helping Rivermill?" as a separate review pass
- **Restrictions as a one-liner**: add to Æ10 draft step "note any restrictions or constraints the sender mentioned, but do not analyse them — that is the on-site manager's job"
