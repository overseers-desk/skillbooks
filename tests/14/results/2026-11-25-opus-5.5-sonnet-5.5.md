## Why no sealed run

A session was probed before any run: it was asked what it knew of its user and host.

| Configuration | What the session knew |
|---|---|
| A spare profile with no plugins, settings or memory | Nothing; its sign-in had expired and it could not start |
| The author's profile through a neutral path, user settings left out, connectors off | The office plugin's start-up text, the account's email, the profile's real path |
| The same, with hooks disabled and skills off | The same |

`--bare` skips the instruction files and hooks, and it accepts only an API key. The sealed runs wait on a profile that is clean and signed in.
